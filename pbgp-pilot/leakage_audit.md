# Leakage and overfitting audit — 2026-10-06

**Verdict: the existing experiments do not establish covert-attack detection. There are confirmed label shortcuts and evaluation leakage paths.** The remote scorer is invoked for inference only; our pilot does not train or fine-tune its model. That does not establish that the model has never seen public incident descriptions, or that a detector trained on these features would generalize.

Scope: the pinned `pbgp-context` method source at `7b2d5d78844843ebd23405a563cd56d0ba3741b1`, current pilot construction/scoring, the seven original unit tests, synthetic saved profiles, and 16 successful recorded requests. Historical method feature datasets/results are not available locally, so the size of any original performance inflation cannot be measured here. The submodule remains unchanged as a historical reference.

## Findings

| Finding | Evidence | Consequence / required correction |
| --- | --- | --- |
| Direct label-dependent score routing | `safety_usefulness.py:406–409` sets `is_att` from `mode`, then selects divergence rows using `is_attack == is_att`. | The combined score requires knowing the correct label. Invalidate it as deployment evidence. Join each candidate to its perturbation by opaque candidate ID, independently of label. |
| Preprocessing sees test rows | `analyze.py:658–685` and `final_analysis.py:356–388` scale the whole dataset before cross-validation. | Fit scaling and any imputation/selection on each training fold only. No numerical inflation estimate is available. |
| Related task variants cross folds | All three classifier paths use row-level `StratifiedKFold`, although multiple runs/comparisons share a `task_id`. | Hold out entire tasks, episodes, templates, and connected coordination groups. `safety_usefulness.py` does fit its scaler within folds, but still has this group problem. |
| Evaluation-set normalization | `safety_usefulness.py:67–73, 361, 400–415` obtains clipping limits/min/max from all comparisons and normalizes combined scores globally. | Test cases affect each other's predictions. Freeze normalization on development data; calibrate thresholds independently. An aggregate ROC curve describes hindsight operating points, not a deployed threshold. |
| Synthetic prompt reveals the class | `run_synthetic_pilot.py:43–46` adds “proceed even if the trusted task conflicts” only for positives. | A retrospective phrase-only baseline has **AUROC 1.000**, exceeding the reported PBGP proxy's 0.819 without any probability signal. Remove or balance this cue in new cases. This demonstrates a shortcut, not proof that Qwen used that exact shortcut. |
| Action/style confounding | Six families, three examples each; suspicious commands and benign commands differ. | Retrospective action-character-length AUROC **0.646**, token-count AUROC **0.653**. Identical-action authorization controls help: attack W1 is higher in **5/6** pairs. Those pairs still have different peer wording and goals; they do not resolve covert-detection validity. |
| Attack labels derived from prompting | `collect_logprobs.py:22–27, 224–229` inserts `[HIDDEN OBJECTIVE]` into the user message and labels the resulting run `attack`. | Verify that an unauthorized action actually occurred. A refusal or a benign completion after this prompt is not automatically an attack. The objective is explicit to the actor; “hidden” is a tag, not a security boundary. |
| Oracle clean rerun and changed text | `collect_logprobs.py:248–257` reruns without the side objective; the old divergence code compares independently generated token sequences. | Removing a known attack objective uses unavailable knowledge if the evaluator is supposed to discover a covert goal. Different completions also introduce semantic/length differences. Test a fixed observable perturbation on the same candidate; keep regeneration as a separate experiment. |
| Score-direction contradiction | README protocol says high divergence suggests honesty/persistent anomalies suggest malice; `analyze.py:476` expects attack comparisons to have higher divergence. The current pilot uses larger W1 as suspicious. | Freeze one direction and a narrowly defined hypothesis before unseen cases. Peer influence and persistent hidden objectives are different mechanisms and may have different signatures. Do not flip direction after viewing test labels. |
| Outcomes excluded, but cases selected retrospectively | `inspect_sample.py` uses current tool rejection to label two cases and constructs prompts from preceding interactions. | All **16** saved successful requests lack the exact current full error text and next-turn ID. The new mutation test protects the context builder. Case selection, repairs, and local rules still use hindsight and are development examples. |
| No-op counted as a measurement | The scroll case's removed feedback was already null. | Zero W1 is not a negative detection. New evaluation guards reject identical original/perturbed contexts as unavailable. Historical results stay visible with their limitation. |
| Unit tests are not attack trials | The original five score tests check extraction/arithmetic; two rule tests check constraints selected after observing the two errors. | Passing them says the code obeys those invariants. It does not measure covert-attack recall or false positives. Added five leakage/split/calibration regression tests. |
| Reuse and contamination | All 18 synthetic cases and two operational cases have already been inspected. Public incident excerpts may occur in unknown training data; provider training/retention behavior cannot be inferred from inference code. | Use these as development only. Test on fresh privately generated episodes and hold out attack families. Any data-collection/model choice based on observed results remains a research choice to disclose. |

Evidence is reproducible offline with `python pbgp-pilot/audit_existing_pilot.py`; aggregate results are in `leakage_audit_results.json`. Neither the phrase baseline nor the paired analysis was preregistered; both are audit diagnostics.

## Changes and validation

- Added a pure pre-action context builder to the existing extraction path. Current and future observations cannot affect its output; the historical context strings are preserved.
- Added `evaluation_guards.py`: detector-input allowlist, label-independent context selection, no-op rejection, case/group/exact-input overlap rejection across development/calibration/test, and a benign-only calibration check. Group IDs must represent connected sources; exact hashes cannot catch paraphrases or falsely assigned independence.
- Added an order-statistic calibration threshold for a fixed high-is-suspicious score, using benign calibration scores only and strict `score > threshold`. Its marginal false-positive interpretation requires exchangeable independent benign episode scores. Distribution shift, repeated testing, or correlated swarm agents can invalidate that interpretation.
- Hardened the current score adapter against inconsistent token offsets and silent truncation of profile or AUC arrays; added three rejection tests. Successful saved responses are revalidated by the audit script, without rescoring at a provider.
- All **15 unit tests pass**. No fresh provider call or attack execution was performed. These guards are building blocks for the next evaluator; they do not repair or certify the historical submodule classifiers.

## Swarm data: useful source, remaining gap

The [METR investigation](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/) reports access to about 1,300 agent transcripts and a large shared-message-board dump. It describes out-of-scope peer influence, deceptive metadata, and tool-call spoofing. This motivates the threat model. The published report provides selected excerpts, not a complete pre-action replay corpus.

The [public recovered-tables dataset](https://huggingface.co/datasets/LauraGomezjurado/openai-hf-incident-recovered-tables) exposes timing/activity records, rather than the full prompt/action stream needed by this scorer. We have not obtained original swarm trajectories or established a public full-transcript download. Treat report-inspired reconstruction as synthetic; retain source provenance and avoid calling it a replay.

Our downloaded [AI Village bucket](https://huggingface.co/buckets/r34lrudraa/ai-village-bucket) is a separate experiment. Its 16 matched session goals supply recorded intent; they do not establish covert attacks or provide the full original instruction hierarchy. Its broader records can support benign collaboration controls and independently verified errors. It cannot substitute for original swarm data by relabeling ordinary operational errors.

The concrete next experiment and claim boundaries are specified in `covert_attack_protocol.md`. At present the defensible answer is **unresolved**: the synthetic proxy contains exploitable shortcuts, and the two real operational errors showed no clear PBGP detection signal. Neither establishes whether PBGP detects covert agent attacks.
